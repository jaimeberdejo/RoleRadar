<objective>
Build the LLM extraction module `llm_client.py`: a thin, injectable wrapper over
`instructor.from_anthropic(Anthropic())` that turns raw CV text into a typed `CVProfile`
via `response_model=CVProfile`. This is the structured-extraction core of CV-01 (PDF → CVProfile
via Pydantic + Instructor) and CV-02 (the CVProfile carries experiencia/skills/formación/años/dominios).

Purpose: Isolating the LLM call behind `build_instructor_client()` means the parser (Plan 04)
and all tests mock at one seam — no Anthropic SDK internals are touched. This module has no
dependency on extractor.py or cache.py, so it builds in parallel with Plan 02.

Output: `app/cv/llm_client.py` plus tests that verify it calls the client correctly with
`response_model=CVProfile` and returns the typed profile (LLM mocked, no network).
</objective>

    Implement exactly:

      def build_instructor_client() -> instructor.Instructor:
          """Construye el cliente instructor sobre Anthropic. Inyectable para tests."""
          return instructor.from_anthropic(Anthropic())

      def extract_cv_profile(raw_text: str, client: instructor.Instructor) -> CVProfile:
          """Llama al LLM para extraer un CVProfile estructurado del texto del CV."""
          model = os.getenv("ANTHROPIC_MODEL_CV", "claude-haiku-4-5-20251001")
          return client.messages.create(
              model=model,
              max_tokens=4096,
              system=(
                  "Eres un extractor de CVs preciso. "
                  "Extrae ÚNICAMENTE lo que aparece explícitamente en el texto. "
                  "No inventes datos. Si un campo no aparece, déjalo vacío o None. "
                  "Para anios_experiencia_total, estima sumando la duración de los empleos "
                  "a partir de las fechas indicadas."
              ),
              messages=[
                  {
                      "role": "user",
                      "content": f"Extrae el CVProfile del siguiente CV:\n\n{raw_text}",
                  }
              ],
              response_model=CVProfile,
              max_retries=2,
          )

    CRITICAL constraints:
    - Use `client.messages.create(...)` (from_anthropic surface) — NOT `client.create(...)`.
    - Model default MUST be the string "claude-haiku-4-5-20251001" read via os.getenv with
      env var name ANTHROPIC_MODEL_CV. Do not hardcode any other model id.
    - ANTHROPIC_API_KEY is read by the Anthropic() SDK from the environment — never reference
      or hardcode the key value in this file; never log it.
    - Prompt-injection mitigation: the CV text goes ONLY into the user message content; the
      system prompt is a fixed string with no f-string interpolation of CV content.
  </action>

| Boundary | Description |
|----------|-------------|
| CV text → LLM prompt | Untrusted CV content crosses into the LLM call |
| process → Anthropic API | Outbound LLM call authenticated by ANTHROPIC_API_KEY (env only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-01-06 | Tampering | prompt injection via malicious CV text | mitigate | CV text passed only as user message content; fixed system prompt with NO f-string interpolation of CV content (verified by code review + test that system string is constant) |
| T-01-07 | Information Disclosure | ANTHROPIC_API_KEY leakage | mitigate | key read by Anthropic() SDK from env only; never referenced/logged/hardcoded in llm_client.py (grep gates: no ANTHROPIC_API_KEY, no sk-ant in source) |
| T-01-08 | Spoofing | wrong/deprecated model id causing 404 | mitigate | default pinned to verified claude-haiku-4-5-20251001; configurable via ANTHROPIC_MODEL_CV |
