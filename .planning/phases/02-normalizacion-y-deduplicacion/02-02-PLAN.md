<objective>
Construir la NORMALIZACIÓN de ofertas: convertir listas de payloads crudos heterogéneos
+ un identificador de `source` en `Job`s tipados con id estable, mediante un registry de
mappers por fuente (un mapper de ejemplo `arbeitnow` con campos reales + un `generic` de
fallback, ambos marcados como AJUSTABLES). El facade `normalize_jobs()` es batch-resiliente:
una oferta mal formada va a `errors` y nunca tumba el batch.

Purpose: es la primera mitad de Phase 2 (la entrada del pipeline). El scoring (Fase 3) y los
endpoints (Fase 4) consumirán estos `Job`s. Implementa NORM-01..04 y QA-02.
Output: app/dedup/normalize.py, app/dedup/mappers.py, app/dedup/__init__.py (solo normalize_jobs),
tests/dedup/test_normalize.py.

Este plan corre en PARALELO con Plan 03 (dedup helper modules): no comparten ficheros.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n → normalize_jobs() | Los payloads crudos son no confiables (claves faltantes, tipos erróneos, HTML, claves extra) y cruzan aquí |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Denial of service | normalize_jobs() con payload mal formado | mitigate | try/except por oferta acumulando en `errors`; una oferta mal formada nunca tumba el batch (NORM-04); validación Pydantic de Job en el mapper |
| T-02-04 | Tampering | HTML inyectado en `description` (Arbeitnow) propagado downstream | mitigate | arbeitnow_mapper hace `re.sub(r"<[^>]+>", " ", desc)`; Job.description guarda texto limpio; HTML original solo en Job.raw. No se hace eval/exec del HTML |
| T-02-05 | Information disclosure | id derivado de campos del payload | accept | sha256 hex no expone material sensible; mismo patrón que Phase 1 cache, no es secreto |
| T-02-06 | Server-Side Request Forgery | URLs en los payloads | accept | Este servicio NO hace fetch de URLs (lo hace n8n); las URLs solo se almacenan como strings |
</threat_model>
