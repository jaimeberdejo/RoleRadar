**Sección 3 — Paso a paso nodo a nodo**

Cada nodo como sub-encabezado `### Nodo N: <nombre>`.

**Nodo 1: Schedule Trigger**
- Tipo de nodo: "Schedule Trigger".
- Interval: Custom (Cron). Expression: `0 8 * * *` (08:00 hora local del servidor n8n).
- Por qué una vez al día: JSearch free tier es limitado en peticiones; una ejecución
  matutina obtiene las ofertas publicadas el día anterior.

**Nodo 2a: HTTP Request — Arbeitnow**
- Método: GET.
- URL: `https://www.arbeitnow.com/api/job-board-api`.
- Autenticación: ninguna (API pública y gratuita).
- La respuesta tiene forma `{ "data": [...offers...], "links": {...} }`.
  Las offers están en el campo `data`.
- Renombrar el nodo a `Arbeitnow` (el Code node del paso 3 lo referencia por nombre).
- Añadir query params de filtrado si la API los soporta (p.ej. `?tags=AI`).

**Nodo 2b: HTTP Request — JSearch (RapidAPI)**
- Método: GET.
- URL: `https://jsearch.p.rapidapi.com/search`.
- Query params: `query` (p.ej. `AI Engineer Barcelona`), `page=1`,
  `num_pages=1`, `date_posted=today`.
- **AUTENTICACIÓN — VER SECCIÓN 4 DE SEGURIDAD.** Las cabeceras van aquí:
  - `X-RapidAPI-Key: <tu-rapidapi-key>` — guardar como credencial n8n
    (Header Auth), nunca como texto plano.
  - `X-RapidAPI-Host: jsearch.p.rapidapi.com`.
- La respuesta tiene forma `{ "data": [...offers...], "status": "OK" }`.
  Las offers están en el campo `data`.
- Renombrar el nodo a `JSearch`.
- Para añadir otras fuentes (FlyByAPIs u otras), repetir este patrón: otro HTTP
  Request + otra entrada en el Code node con su `source` correcto.

**Nodo 3: Code — construir el body ProcessRequest**
- Tipo: "Code" (JavaScript). Modo: "Run Once for All Items".
- Por qué un Code node y no Merge: las dos fuentes llegan con formas distintas y
  hay que envolverlas en el envelope `{ sources: [...] }` con el valor `source`
  correcto para que el servicio enrute al mapper adecuado. El valor del campo
  `source` DEBE coincidir con los reconocidos en el servicio
  (`"arbeitnow"`, `"jsearch"`, o cualquier string para el mapper genérico).
- Snippet (ajustar los nombres de nodo si se renombraron de forma distinta):

```javascript
const arbeitnow = $('Arbeitnow').first().json.data || [];
const jsearch   = $('JSearch').first().json.data   || [];

return [{
  json: {
    sources: [
      { source: 'arbeitnow', offers: arbeitnow },
      { source: 'jsearch',   offers: jsearch   },
    ],
  },
}];
```

**Nodo 4: HTTP Request — POST /jobs/process**
- Método: POST.
- URL (ajustar según entorno):
  - Dev con n8n en Docker, Mac/Windows: `http://host.docker.internal:8000/jobs/process`.
  - Dev con n8n en Docker, Linux: IP del host (`ip addr show docker0 | grep inet`)
    o añadir el contenedor del servicio a la misma red Docker de n8n.
  - Producción: `https://<tu-dominio>/jobs/process`.
  - Referencia completa en `../README.md#cómo-n8n-alcanza-el-servicio`.
- Body Content Type: JSON. Body: `={{ $json }}` (toma el objeto del Code node).
- Cabeceras obligatorias:
  - `Content-Type: application/json` (n8n suele añadirla automáticamente con JSON body).
  - `X-API-Key: {{ $env.API_KEY }}` (solo si `API_KEY` está configurada en el servicio;
    usar credencial Header Auth de n8n; ver sección 4).
- **Timeout (importante):** En Options → Timeout, poner un valor alto, p.ej. `300000` ms
  (5 minutos). El primer arranque descarga el modelo BGE-M3 (~2.3 GB); además, el scoring
  llama a OpenAI por cada oferta única. Los runs posteriores son más rápidos.
- La respuesta es un `ProcessResponse`:
  ```json
  {
    "results": [
      { "job": {...}, "score": { "score_total": 82, ... }, "ya_visto": false }
    ],
    "errors": []
  }
  ```
  `results` viene ordenado por `score_total` DESC. Ver contrato completo en
  `../README.md#contrato-post-jobsprocess`.

**Nodo 5: Split Out — una oferta por item**
- Nodo "Split Out".
- Field To Split Out: `results`.
- Tras este nodo, cada item del flujo es un elemento de `results` con los campos
  `.job`, `.score` y `.ya_visto`.

**Nodo 6: Filter — quedarse con lo relevante y nuevo**
- Nodo "Filter". Combinar con AND:
  - Condición 1 (Number): `{{ $json.score.score_total }}` >= `70`.
  - Condición 2 (Boolean): `{{ $json.ya_visto }}` is `false` (evita reenviar
    ofertas ya notificadas en días anteriores; el servicio marca el flag,
    n8n solo filtra por él).
- El umbral 70 es ajustable. También se puede filtrar por `recommendation`:
  incluir solo `"strong_fit"` y `"good_fit"` si se quiere ser más selectivo.

**Nodo 7: Code — formatear el digest (opcional pero recomendado)**
- Agrupa todos los items filtrados en un único mensaje para Telegram.
- Tipo: "Code" (JavaScript). Modo: "Run Once for All Items".
- Snippet:

```javascript
const items = $input.all();
if (items.length === 0) {
  return [{ json: { text: 'No hay ofertas relevantes hoy.' } }];
}
const lines = items.map(i => {
  const j = i.json.job;
  const s = i.json.score;
  return `• *${j.title}* — ${j.company} (${j.location || 'ubicación desconocida'})\n`
       + `  Score: ${s.score_total} · ${s.recommendation}\n`
       + `  ${j.url || '(sin URL)'}`;
});
return [{
  json: {
    text: `*Ofertas de hoy (${items.length})*\n\n` + lines.join('\n\n'),
  },
}];
```

Sin este nodo, el nodo Telegram se ejecuta una vez por item (un mensaje por
oferta). Ambas opciones son válidas.

**Nodo 8: Telegram — enviar el digest**
- Nodo "Telegram", operación "Send Message".
- Credencial: crear bot con @BotFather → obtener token → crear credencial
  "Telegram API" en n8n con ese token.
- Chat ID: cómo obtenerlo — escribir un mensaje al bot y llamar a
  `https://api.telegram.org/bot<TOKEN>/getUpdates`, o usar @userinfobot.
- Parámetros:
  - Chat ID: tu chat id (número o `@canal`).
  - Text: `={{ $json.text }}` (del nodo 7).
  - Additional Fields → Parse Mode: `Markdown`.

**Nodo 8-bis: Variante Email (breve)**
Alternativa al nodo Telegram: usar "Send Email" (SMTP) o el nodo "Gmail".
El cuerpo del digest se construye igual en el Nodo 7 (usar HTML en vez de
Markdown si el cliente de correo lo requiere). No se detallan las credenciales
SMTP aquí; seguir la documentación del nodo correspondiente en n8n.

**Sección 6 — Programación y costes**

- Schedule: `0 8 * * *` (una vez al día). JSearch free tier tiene límite de
  peticiones mensuales; una ejecución diaria está bien dentro del tier gratuito.
- Timeout del nodo /jobs/process: 300 000 ms mínimo. La primera ejecución
  descarga BGE-M3 (~2.3 GB); los runs posteriores usan el modelo ya cacheado y
  son sensiblemente más rápidos.
- Coste de OpenAI: el scoring llama a `gpt-4o-mini` para el CVProfile y a `gpt-4o`
  para scoring. Con 20-50 ofertas únicas diarias el coste es marginal.
- Idempotencia: `ya_visto: true` en el response marca ofertas que ya estaban en el
  storage de días anteriores. El Filter del nodo 6 las excluye del digest, pero
  el servicio las sigue procesando (actualiza el score si la descripción cambia).

**Sección 7 — Troubleshooting**

Tabla o lista de problemas comunes:

| Síntoma | Causa probable | Solución |
|---|---|---|
| HTTP 404 `No hay CVProfile cacheado` | El CV no se subió antes de ejecutar el flujo | `curl -X POST http://localhost:8000/cv/parse -F "file=@mi_cv.pdf"` |
| HTTP 401 `Invalid or missing API key` | Falta la cabecera `X-API-Key` o el valor es incorrecto | Añadir credencial Header Auth en n8n con el mismo valor de `API_KEY` del `.env` del servicio |
| `Connection refused` / no llega al servicio | URL incorrecta para el entorno (Linux vs Mac/Win vs prod) | Mac/Win Docker: `host.docker.internal:8000`; Linux: IP del host o red compartida en compose |
| Timeout en el primer run | Primera descarga de BGE-M3 (~2.3 GB) + llamadas OpenAI | Subir el timeout del nodo a 300 000 ms o más; esperar a que el modelo se descargue |
| `results: []` o arrays vacíos | La API de empleo no devolvió datos o el campo `data` tiene otro nombre | Inspeccionar la respuesta cruda del HTTP Request node de Arbeitnow/JSearch y ajustar la ruta en el Code node |
| Ofertas relevantes no llegan por Telegram | El Filter es demasiado estricto o `ya_visto` siempre true | Bajar el umbral de score o revisar que /cv/parse se ejecutó con el CV correcto |
